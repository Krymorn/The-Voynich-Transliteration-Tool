# Measuring the text

[Back to the README](../README.md)

What the numbers mean, and which ones are worth paying attention to.

A general point first. Most of these statistics are **checks on your pipeline, not targets to
hit**. A substitution mapping swaps letters around; it cannot turn a strange text into a
normal one. If a measurement changes dramatically after you apply your mapping, the usual
explanation is that your mapping is adding or removing information — expanding one glyph into
three letters, say — rather than that you have discovered anything.

## Entropy

```bash
tvtt run --plugin entropy
```

Entropy measures how predictable the text is. `h0` treats every character as equally likely,
`h1` accounts for how common each character is, and `h2` — the important one — measures how
predictable a character is once you know the one before it.

| Text | h2, roughly |
|---|---|
| Voynich Manuscript | **2.4 bits** |
| Latin, Italian, English, Hebrew | **3.0 to 3.5 bits** |

That gap is the central strange fact about Voynichese. The text is far more predictable than
any European language — knowing one character tells you unusually much about the next. It is
the single hardest thing for any "it is just language X in a simple cipher" theory to
explain, because a simple substitution cannot change h2 much at all.

Which is exactly why you should read your own h2 as a sanity check. Your output should land
near the manuscript's value. If it suddenly looks like Latin, the extra unpredictability came
from your mapping, not from the manuscript.

## Word length

```bash
tvtt run --plugin word_length
```

Voynich word lengths are unusually tight: a sharp peak at five glyphs, very few one- and
two-letter words, and a tail that thins fast. The distribution looks close to binomial, which
is not what natural language does.

European languages spike at two or three letters, because function words — *et*, *in*, *the*,
*di*, *e* — are short and extremely common. The absence of that spike is one reason the
"function words are missing" observation keeps coming up.

If your mapping produces a language-like length distribution from this, check whether it is
doing so by expanding single glyphs into multiple letters. That is allowed, but it is a
strong assumption and the numbers should not be read as independent confirmation of it.

## Vocabulary

```bash
tvtt run --plugin vocabulary
```

- **Type/token ratio** — distinct words divided by total words. Sensitive to text length, so
  it is only comparable between texts of the same size.
- **MATTR** — a moving-average version that is not length-sensitive, and the one to use when
  comparing sections.
- **Hapax legomena** — words appearing exactly once. Natural languages run high here.
- **Heaps' law** — how vocabulary grows as text is added, fitted as an exponent.

## Zipf's law

```bash
tvtt run --plugin zipf
```

Word frequency against rank. Voynichese fits Zipf's law well, which gets quoted as evidence
that it is a real language.

Be careful with that. Zipf's law is remarkably easy to produce: random text with realistic
word-length variation fits it, and so does text generated by copying and modifying earlier
words. The `shuffles` feature demonstrates this directly — Zipf survives almost every kind
of shuffling you can do to a text. A good Zipf fit tells you very little on its own.

## Slot grammar

```bash
tvtt run --plugin slot_grammar
```

This tests Jorge Stolfi's observation that Voynich words look **assembled rather than
spelled**: a fixed sequence of optional parts, each drawn from a small set, always in the
same order — a crust, a mantle and a core. A very large share of the vocabulary fits such a
template.

Nothing like this is true of Latin or Italian words.

If your output still fits the template, the manuscript's structure came through your mapping
intact, which is what should happen. A mapping that destroys it has probably done something
drastic.

## Repetition

```bash
tvtt run --plugin repeats
```

How much the text repeats itself, and at what distance. Voynichese repeats far more than
natural language: the same word twice or three times in a row is common, and near-identical
words cluster together.

This is the observation the Timm and Schinner self-citation model is built on, and it is what
the `synthetic` baseline reproduces. See [Checking a mapping
honestly](validation.md#synthetic).

## Line effects

```bash
tvtt run --plugin line_effects
```

In ordinary writing, where a word falls on the page tells you nothing about which word it is.
In this manuscript it does:

- line-initial words draw on their own restricted vocabulary
- certain glyphs, particularly the gallows, cluster at line and paragraph beginnings
- first lines of paragraphs behave differently from later ones
- some glyphs avoid line-final position

This is the LAAFU effect, "line as a functional unit". No natural language written normally
does it, so any complete theory of the text has to account for it. You can isolate it with
`--lines first` and `--words first`; see [Choosing what to work
on](selections.md#line-and-word-position).

## Vowels

```bash
tvtt run --plugin vowels
```

Sukhotin's algorithm guesses which characters are vowels from how they alternate with the
rest, with no knowledge of the language. It works well on real languages.

TVTT runs it and then **tests whether the answer means anything**, by checking whether the
classes it found really do alternate more than chance would give. On Voynichese the algorithm
returns an answer, as it always does, but the test tends not to support it. Reporting the
answer without the test is how this measure gets misused.

## Comparing sections

```bash
tvtt run --plugin section_report
```

Every headline statistic, computed per section, with the differences shown. Often the single
most informative output in the tool.

Currier's A and B appear immediately — word lengths, glyph frequencies and vocabulary all
shift. So does anything odd about your mapping: a mapping that works only where you developed
it shows up here as one column that does not match the rest.
